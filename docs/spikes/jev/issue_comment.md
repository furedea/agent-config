## 結論

**採用する．jev-lint を第一候補とし，#74 のバックエンド抽象の裏に置く．自作は今は見送る．**

- 両ツールとも，適合率・再現率・時間・更新時期の基準を満たしました．精度では差がつきません．見逃しは各 2 件で，互いに別の関数です．
- 差が出るのは設計との相性です．jev-lint は ast-grep の matcher で対象を抜き出す形で，Issue の方針と同じです．トークンと費用を報告します．Nix の `nodejs` だけで，CGO なしに固定版を動かせました．
- jevlint の利点は provider が多いことです（OpenAI，OpenRouter）．欠点は，トークンを報告しないことと，Nix の clang でビルドできないことです．
- 基準の「Nix で入る」は，どちらも nixpkgs にないので文字どおりには満たしません．「Nix 経由で固定版を再現して動かせる」に読み替えました．その場合，jev-lint は満たし，jevlint はシステムの clang に頼るため満たしません．
- 自作の見積もり：ast-grep で関数を抜き出し，TypeSafe の systemone API へ 1 ファイル 1 リクエストで問い合わせる最小実装は，Python で 200 行前後と，テストが必要です．1〜2 日の見込みです（実装していない見積もりです）．ツールが止まったり方針が合わなくなったら，この選択肢に切り替えます．

## 結果の限界

- 例は 42 件（違反 21，適合 21）で，作者が付けたラベルです．曖昧な例を入れていないので，現実のコードより易しい可能性があります．
- 各ケース 1 回の実行です．README は結果が非決定的だと述べています．再現率 0.90 は 21 件中 19 件で，信頼区間は広く，2 ツールの差は誤差の範囲です．
- 閾値は調整していません．jev-lint の自作規則の既定は cutoff 2 です．jevlint は既定のままです．
- 結果の表の `confidence` は補助値で，判定には使っていません．jev-lint のスコアは別項目の `value` です．
- 時間は，jev-lint は自己申告値，jevlint は実行時間をファイル内の関数数で割った値です．
- 保守状況は，どちらも作成から約 6〜7 週間で，今回の更新時期の基準は満たしても，長期の実績はありません．npm の jev-lint は 09-24 以降公開がありません．
